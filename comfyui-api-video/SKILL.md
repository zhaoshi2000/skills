# ComfyUI API 生视频

以用户指定的服务器、素材目录、排除目录、画幅、时长和声音要求为准。直接调用 ComfyUI API，不改用其他网站或桌面自动化。只生成用户要求的新内容；已有视频可作参考，不得冒充新成片。不要把密钥、Cookie、私有素材或任务日志提交到公开仓库。

## 准备工作流

1. 查询 `/system_stats`、`/queue`、`/object_info`，核实显卡、可用模型、节点的实际 API 名称与输入。优先使用服务器已有的节点和模型；不要凭 UI 标签猜输入键。可参照 [已验证的 H3 链路](references/verified-h3.md)，但每次都重新核对服务器。
2. 检查用户允许使用的角色卡、场景图、道具图和原有工作流。每张参考图明确绑定角色、场景或道具；不要把未出镜的说话人或被提及的人物自动画进镜头。只有剧情需要时才加入道具参考。只上传当前镜头需要的素材。
3. 按镜头计划构建 **API 格式**的 prompt 图，先生成短镜头，再按剧情顺序剪辑。不同景别与角度应有真实切镜；人物外观、服饰、左右站位和场景布局跨镜头保持一致。参考图顺序、节点连接及提示词中的说明必须一致。可为困难镜头加入正确的首帧锚点；不要让镜头内的同一人物消失后在另一位置重现。
4. 用户追求画质时，先在当前硬件上验证一个代表镜头，再决定原生分辨率、帧数和步数。更长时长或更高分辨率未必提升质量。不要把放大版称作原生 1080P/4K，也不要把提示词中的相机规格当作模型真实拍摄元数据。

## API 工具

`scripts/comfy_video_api.py` 只用 Python 标准库。它接受明确的服务器地址和已准备好的 API prompt JSON；不自动构图、不自动重试，也不处理身份验证。示例：

```bash
python scripts/comfy_video_api.py --server http://127.0.0.1:8188 inspect --node MiniMaxH3ReferenceToVideo
python scripts/comfy_video_api.py --server http://127.0.0.1:8188 upload reference.jpg
python scripts/comfy_video_api.py --server http://127.0.0.1:8188 submit shot_api.json
python scripts/comfy_video_api.py --server http://127.0.0.1:8188 wait PROMPT_ID --timeout 3600
python scripts/comfy_video_api.py --server http://127.0.0.1:8188 download PROMPT_ID --output-dir ./deliverables
```

上传后把返回的服务器文件名写入工作流，并记录本地文件与服务器文件名的对应。提交后立即保存 `prompt_id`。等待超时、连接中断或状态未知时，先用同一 ID 查询 `/queue` 和 `/history/{prompt_id}`，不得盲目再次提交。脚本的 `wait` 返回 0 表示历史记录确认成功，1 表示失败，2 表示超时；`download` 只提取历史记录中成功任务的视频输出。可用 `/ws?clientId=...` 观察采样步数；采样结束后仍需等待解码和保存。

## 镜头与声音验收

- 抽查每镜开头、中间、结尾与切点。检查角色脸、服装、站位、手部、穿模、重复人物和场景布局。发现问题时只重做相关镜头，保留已合格镜头。提示词中的“禁止”不等于画面验收通过。
- 用实际帧数、帧率、分辨率及媒体流检查时长和音轨。无音轨时明确告知用户。用户要求无 BGM、无字幕时，检查输出中确实没有音乐和烧入文字。
- 同期音频需要模型实际输出音频，并连接音频解码与视频封装节点。若台词必须准确符合 SRT 或跨多个镜头，优先每条台词只合成一次音频，再在时间轴分配片段，不为每镜重复合成整句。
- 为同一角色固定声音配置；青年、中年等年龄段可存为同一角色的不同声线版本。声音克隆、变声或 TTS 能力须先检查当前服务器节点和凭据，不得把尚未验证的能力写成已完成。声线参考录音须保持干净的单人声音。
- 交付实际新生成的视频、可复现的 API 图、参考文件映射与任务 ID。保留原生版本；如另做放大或补帧，清楚标记。不要覆盖用户的原始素材和已有成片。
